# 북마크 스레드와 댓글 묶음 백업

## 적용 범위

Chrome 빌드 `1.4.3-chrome.5`. 북마크한 게시물을 기준으로 원문과 연결된 댓글·대댓글을 하나의 Markdown 스냅샷으로 저장한다.
작성자가 같은지 여부와 무관하게 답글 대상 ID를 따라 연결한다. 다른 대화의 추천 게시물은 포함하지 않는다.
북마크한 게시물 자체가 댓글이면 그 게시물 아래의 답글만 포함하며, 상위 게시물의 다른 댓글은 섞지 않는다.

## 사용

확장 프로그램 및 X 탭을 새로고침한다. 자동 백업 설정에서 기존처럼 북마크 범위를 사용한다.
북마크 원문을 열고 댓글을 스크롤하거나 답글 더 보기를 펼친다. TweetDetail 수집 모듈이 켜져 있어야 한다.
추가 댓글이 수집되면 댓글만 개별 파일로 보내지 않고 원문과 기존 댓글을 모두 포함한 새 스냅샷을 만든다.
이미 브라우저 DB에 있는 댓글도 기존 수집 데이터 추가 또는 페이지 재시작 시 묶음에 포함한다.

## 파일 정책

- 최초 스냅샷: `raw/articles/twitter-web-exporter/x-<북마크 ID>.md`
- 댓글 추가·본문 변경: `revisions/x-<북마크 ID>-<내용 해시>.md`
- 변경본도 댓글만의 증분 파일이 아니라 원문과 수집된 댓글 전체가 들어 있는 독립적인 Markdown이다.
- 기존 raw 파일은 덮어쓰거나 삭제하지 않는다. 최신 생성 파일은 백업 상태의 최근 저장 경로에서 확인한다.
- 같은 내용은 다시 저장하지 않는다. 댓글 도착 순서가 달라도 같은 정렬과 해시를 사용한다.
- 댓글별 작성자·본문·게시 시각·원문 URL·상위 답글 링크·답글 깊이·미디어 URL을 보관한다.

## 정확성 및 한계

북마크 목록만 열었다고 전체 댓글이 로드되는 것은 아니다. 이 기능은 추가 X API 요청이나 자동 스크롤을 실행하지 않는다.
`replies_captured`에 포함한 댓글 수를 기록하고 `replies_complete: false`를 유지한다.
`capture_scope: loaded-descendants-only`로 브라우저에 로드되고 부모 관계가 확인된 범위임을 명시한다.
중간 부모가 없는 답글은 보류하며, 부모가 나중에 수집되면 다시 연결한다.
최대 댓글 1,000개, 묶음 4 MiB를 적용한다. 개수 제한 시 `limited: true`와 안내문을 넣고 크기 초과 시 오류를 반환한다.
삭제·비공개·미로드 댓글은 복원하지 못하며, 미디어 바이너리는 기존처럼 별도 다운로드한다.

## 구현과 검증 — 2026-09-23

- 사이트 DB: v4에 부모 ID·대화 ID 인덱스만 추가했다. 기존 v2/v3 선언과 저장 데이터를 유지한다.
- `thread-source.ts`: 기존 DB에서 북마크와 연결된 조상·자손을 찾는다. 추가 네트워크 수집은 하지 않는다.
- `thread.ts`: 부모 우선 정렬, 관계 검증, 원문+댓글 Markdown, 수집 범위 및 개수 기록.
- `thread-queue.ts`: 여러 번 제출한 댓글을 합치고, 그래프와 작업을 같은 트랜잭션으로 저장한다.
- 확장 DB: v2의 threadItems에 목적지·북마크별 구성원을 보관한다. 완료 작업에도 댓글 구성을 유지해 일부 응답이 이전 댓글을 지우지 않게 한다.
- TweetDetail 파서: 여러 AddEntries/AddToModule을 모두 처리하고 섞여 있는 페이지네이션 커서를 건너뛴다.
- 댓글 데이터는 확장 프로그램 내부에서만 모으며, REST API 키나 권한 범위는 변경하지 않았다.

`pnpm check:chrome`: 타입 검사·린트·Chrome 빌드·31개 테스트 통과.
추가 단위 테스트 7개 및 별도 Chromium 통합 테스트 1개가 포함되어 있다.
중첩 댓글, 부모보다 먼저 수집한 댓글, 북마크한 중간 답글의 범위, 다른 대화 제외, 순서 무관 해시,
수집 범위·제한 안내, 기존 댓글 백업, 뒤늦은 댓글의 전체 묶음 생성과 재조회 중복 방지를 확인했다.
기존 UserScript 빌드, ZIP 패키징 및 무결성 검사도 통과했다.
검증은 임시 Chromium 프로필·모의 X 응답·모의 Obsidian API로 진행했다. 실제 볼트 쓰기 테스트는 하지 않았다.
